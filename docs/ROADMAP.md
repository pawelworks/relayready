# RelayReady roadmap

Planning horizon: October 2026 through September 2027. Owner: **Pavel Mihai
Lucian**, <lucian.pavel@pawelworks.com>. These are proposed priorities and exit
criteria, not committed delivery dates, funded work or promised adoption.

## Public baseline already established

The public [repository](https://github.com/pawelworks/relayready) and issue
tracker are available. [Publication PR #1](https://github.com/pawelworks/relayready/pull/1)
merged at `c3c91545f6c7584a7f093e8904a7e8d26fc22d1a`; all twelve hosted matrix
jobs passed in [CI run 35541220709](https://github.com/pawelworks/relayready/actions/runs/35541220709).
The reviewed public import has the owner's authorized DCO sign-off. Earlier
unsigned deployment history remains separate and has not been retroactively
signed. These facts resolve the source-publication gates, not foundation
admission or legal asset-transfer review.

## October-December 2026: reviewable public baseline

- Maintain the public repository, contribution process and protected CI checks;
  make subsequent changes through the documented review process.
- Complete the remaining brand, ownership and transfer-scope review in the
  [asset inventory](AAIF_ASSET_INVENTORY.md). A source DCO attestation is not
  foundation-transfer consent or independent legal clearance.
- Publish a traceable pre-release with checksums and known limitations after
  repeating the hosted platform matrix and independent installed-wheel checks
  for that exact release revision.
- Invite external review of the frozen core and experimental continuation
  profile. Keep normative changes on the documented public review process.
- Prepare Sandbox consideration using the [written thesis](AAIF_SANDBOX_THESIS.md)
  and current [TC lifecycle policy](https://github.com/aaif/technical-committee/blob/main/governance/project-lifecycle-policy.md).
  The owner supplied company/signatory details, attested company authority and
  authorized the public application and conditional project transfer.
  [Proposal #44](https://github.com/aaif/project-proposals/issues/44) is submitted;
  respond to review without claiming admission. Actual LF agreements remain unsigned.

Exit: accessible source, an inspectable release, reproducible checks and a
publicly recorded review. None of these imply foundation acceptance.

## January-March 2027: independent interoperability

- Implement an artifact-carrier adapter for A2A and a resource-observation
  adapter for MCP, with explicit provider-specific revision semantics.
- Seek an independent implementation/reviewer to exercise the shared fixtures.
- Test stale revisions, missing observations, conflicting invariants, altered
  input bytes and uncertain side effects. Keep credentials and execution policy
  outside the portable artifacts.
- Recruit a second maintainer from a different organization and an independent
  conduct-reporting/appeal route, subject to actual participation and consent.

Exit: two separately implemented integrations and inspectable conformance
results. An integration is not called verified until exercised in its runtime.

## April-June 2027: live evaluation and hardening

- Run the [predeclared pilot](PILOT_PROTOCOL.md) on authorized, isolated tasks.
- Publish all attempted runs, costs and failures after privacy review, keeping
  real outcomes separate from mock fixtures and browser demonstrations.
- Commission or invite independent security review; track findings openly
  where safe. Evaluate OpenSSF practices without displaying an unearned badge.
- Reassess false escalations and observation freshness from measured data.

Exit: a reproducible live report with limitations and no unsupported efficacy
claim; safety failures block release rather than being averaged away.

## July-September 2027: community-led stabilization

- Propose any continuation-profile stabilization through public review.
- Document migration, compatibility and release-support expectations.
- Seek genuine organizational pilots; record adoption only with permission and
  verifiable evidence. Contributors and maintainers must be actual people.
- Reassess AAIF readiness or, if admitted to Sandbox, progress toward its Growth
  criteria using the then-current policy and observed evidence.

Exit: community-reviewed direction and a candid readiness assessment. If
independent participation or live evidence is insufficient, remain a clearly
labelled experiment rather than declaring production maturity.

## Conditional Sandbox checkpoints

These relative checkpoints apply only if AAIF admits RelayReady; they do not
change the calendar planning horizon above or imply that admission has occurred.

- **At admission:** complete agreed charter/onboarding requirements and state
  in the README that Sandbox is not an endorsement. Expect standard
  infrastructure, not additional foundation services.
- **Six months after admission:** supply candid progress evidence for the TC
  sponsor's checkpoint.
- **Within twelve months after admission:** aim to apply for Growth only with
  production-use evidence from two unaffiliated organizations, six months of
  commits from two organizations, named committers and an acceptance process, plus a
  sponsor-accepted growth plan defining Impact goals. These are future
  graduation gates, not current project claims or Sandbox intake prerequisites.

Missing that window triggers an Emeritus/archival discussion under the policy;
record the outcome without inventing progress.
